0.1) 실습 폴더 규칙: AGENTS.md¶

기본 실습 규칙은 mlops_workshop/AGENTS.md 파일 하나에 들어 있습니다. 실습 zip을 가져올 때 함께 들어오므로 따로 설치할 것이 없습니다. 내용을 읽고 Genie Code가 실제로 읽는지만 확인합니다.

1단계 - 파일 열어 보기¶

  1. Workspace → 내 mlops_workshop 폴더를 엽니다. 맨 위에 AGENTS.md가 있습니다.
  2. 파일을 열어 아래 내용과 같은지 봅니다.
mlops_workshop/AGENTS.md
# HL만도 MLOps 핸즈온 랩 — 실습 폴더 규칙 (AGENTS.md)

> 이 파일은 `mlops_workshop/` 폴더에 있습니다. Genie Code는 이 폴더 안의 노트북·파일을 열었을 때 상위 폴더를 따라 올라가며 이 파일을 읽습니다. 워크스페이스의 다른 업무에는 적용되지 않습니다.

## 응답 방식
- 항상 한국어로 답한다. 코드 주석은 영어로 쓴다.
- 코드를 실행하거나 파일·테이블·모델을 바꾸기 전에 무엇을 할지 3줄 이내로 먼저 말한다.
- 모르는 업무 규칙(경보 기준, 승인 절차 등)은 추측해서 만들지 말고 "ML팀 확인 필요"라고 표시한다.

## 실습 환경
- 실습 데이터는 합성 데이터이며 가상 공장 VP1의 CNC 가공기 24대(라인 3개 × 8대), 10분 간격 센서다.
- 공유 데이터: `mlops_edu_dev.phm_shared` (읽기 전용, 절대 쓰지 않는다). 주요 테이블은 `equipment`, `sensor_readings`, `maintenance_events`, `sensor_readings_incoming`, `maintenance_events_incoming`.
- 실습자는 자기 스키마 `mlops_edu_dev.<내 스키마>`에만 테이블·모델·Job·대시보드를 만든다. 내 스키마는 사용자 인스트럭션에 적혀 있다. 모르면 먼저 묻는다.
- 실습 노트북과 모듈은 이 `mlops_workshop/` 폴더에 있다. 폴더 구조와 `.py` 모듈 이름을 바꾸지 않는다.

## 컴퓨트·패키지
- 서버리스 환경 버전 5를 쓴다. MLflow, scikit-learn 1.6.1, pandas, numpy가 이미 있으므로 `%pip install`을 하지 않는다. 설치 없이 같은 결과가 나오도록 맞춰 둔 실습이다.
- 새 라이브러리가 꼭 필요하면 바로 설치하지 말고, 패키지 이름과 이유를 먼저 알려 확인을 받는다.

## 피처 규칙
- 피처 테이블 `phm_features`는 기본키 `(machine_id, ts)`를 가진 UC 피처 테이블이다. 피처 정의는 `step1/phm_features.py` 하나에만 둔다. 노트북에 피처 계산을 복사하지 않고 모듈 함수를 불러 쓴다.
- 센서 오류값(진동 ≥ 50, 베어링 온도 ≥ 120)과 정지 행(`spindle_rpm = 0`)은 피처 계산 전에 걸러 낸다.
- 시계열이므로 학습·검증은 무작위로 섞지 않고 시간으로 나눈다.

## MLflow·모델 규칙
- 실험 이름: `/Users/<내 이메일>/phm_failure_<내 스키마>`.
- 모델은 Unity Catalog에 `mlops_edu_dev.<내 스키마>.phm_failure_model`로 등록한다. 등록 모델에는 signature가 반드시 있어야 한다.
- 모델 출력은 `step2/phm_model.py`의 `PHMFailureModel` 래퍼로 `fail_prob`·`alert` 두 컬럼으로 통일한다.
- 단계는 별칭으로 표시한다: `@champion`(운영), `@challenger`(검증 대기), `@previous`(직전 champion). Workspace Model Registry의 Stage(Staging/Production)는 쓰지 않는다.
- 모델을 불러올 때는 버전 번호가 아니라 `models:/<이름>@champion`처럼 별칭을 쓴다.

## 하지 말 것
- `@champion`을 노트북에서 직접 옮기지 않는다(Step 2 첫 등록 제외). 승격은 학습 파이프라인 Job의 `validate` → `promote` 태스크가 한다.
- Serving 엔드포인트와 엣지 앱 `vp1-edge-gateway`는 진행팀이 관리한다. 만들거나 고치거나 지우지 않는다.
- 다른 실습자의 스키마·모델·Job을 읽거나 바꾸지 않는다.

## 스킬
- MLflow 기록·UC 등록·별칭은 `phm-mlflow-uc` 스킬, `.py` 학습 파이프라인 Job은 `phm-training-job` 스킬을 따른다. 스킬은 각자 `/Users/<내 이메일>/.assistant/skills/`에 설치되어 있다.

## 대시보드·Genie Agent (Step 6)
- 대시보드와 Genie Agent는 내 스키마의 `phm_predictions`, `model_monitoring`, `model_validation_log`와 공유 `equipment`, `maintenance_events`만 쓴다.
- 설비보전팀이 읽는 문장은 업무 용어로 쓴다: `fail_prob` = 24시간 내 고장 확률, `alert` = 점검 요청 경보, `fail_within_24h` = 실제로 24시간 안에 고장 난 행(정답).
구역 왜 넣었나
응답 방식 실행 전에 계획을 먼저 말하게 해, 무엇이 바뀌는지 알고 승인하게 합니다. 경보 기준 같은 업무 규칙을 지어내지 않게 합니다.
실습 환경 공유 데이터(읽기 전용)와 내 스키마를 구분해, 다른 사람의 데이터에 쓰지 않게 합니다.
컴퓨트·패키지 필요 없는 %pip install을 막습니다. 필요한 라이브러리는 환경 버전 5에 이미 있어, 설치 없이 모두 같은 결과를 얻습니다.
피처 규칙 학습·Job·엣지가 같은 피처 정의를 쓰게 합니다. 시계열을 무작위로 섞는 실수도 막습니다.
MLflow·모델 규칙 실험·모델 이름과 별칭 의미를 고정합니다. 옛 Stage 방식으로 답하지 않게 합니다.
하지 말 것 승격은 파이프라인만, 공용 엔드포인트·앱은 진행팀만 건드리게 합니다.
대시보드·Genie Agent Step 6에서 설비보전팀이 읽을 문장을 업무 용어로 쓰게 합니다.

2단계 - 적용 범위 이해하기¶

  • Genie Code는 지금 열려 있는 노트북·파일의 폴더부터 상위 폴더로 올라가며 AGENTS.md를 찾습니다. step1/1_data_and_features를 열면 step1/ → mlops_workshop/ 순서로 찾아 이 파일을 읽습니다.
  • mlops_workshop 밖의 노트북에서는 이 파일이 읽히지 않습니다. 같은 워크스페이스의 다른 업무에 영향을 주지 않는 이유입니다.

팀 Git 폴더에 두면 버전 관리가 됩니다

운영에서는 AGENTS.md를 팀 Git 폴더(Azure Repos와 연결)에 두면, 규칙 변경을 PR로 리뷰하고 이력을 남길 수 있습니다. 3.3 Azure DevOps 연동과 같은 저장소를 씁니다.
