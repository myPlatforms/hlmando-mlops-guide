5.1) Data quality monitoring (시연)¶

  • 시연 약 5분
  • 노트북 step5/5_1_data_quality_demo
  • 참고

Step 5에서는 구간별 성능을 노트북으로 직접 계산해 model_monitoring에 남겼습니다. 운영에서는 Data quality monitoring이 이 일을 자동으로 합니다.

기능 대상 하는 일
Data profiling (구 Lakehouse Monitoring) 테이블 하나 시간 구간별 통계와 드리프트, inference 프로파일이면 정답 레이블 열이 있을 때 모델 품질 지표까지 계산해 지표 테이블 2개와 대시보드를 만듦
Anomaly detection 스키마 전체 스키마의 모든 테이블을 신선도(freshness)·완전성(completeness) 기준으로 자동 감시

시연 순서¶

  1. 감시용 예측 테이블 만들기: 46~75일(신규 소재 투입 전 15일 + 후 15일)을 champion으로 다시 점수 매겨 phm_inference_log에 저장합니다.
  2. inference 프로파일 만들기: 문제 유형 classification, 예측 prediction, 정답 fail_within_24h, 모델 ID model_version, 시각 ts, 구간 1일.
  3. 결과 보기: Catalog → phm_inference_log → Quality 탭에서 갱신 상태와 대시보드를 엽니다. 신규 소재 투입 뒤 온도·전류 피처의 드리프트가 커지고 날짜별 재현율이 떨어집니다.
inference 프로파일 (새 API, databricks-sdk 0.68.0 이상)
config = DataProfilingConfig(
    output_schema_id=schema.schema_id,
    assets_dir=f"/Workspace/Users/{ME}/databricks_quality_monitoring/phm_inference_log",
    inference_log=InferenceLogConfig(
        problem_type=InferenceProblemType.INFERENCE_PROBLEM_TYPE_CLASSIFICATION,
        prediction_column="prediction", label_column="fail_within_24h",
        model_id_column="model_version", timestamp_column="ts",
        granularities=[AggregationGranularity.AGGREGATION_GRANULARITY_1_DAY]),
    slicing_exprs=["line_id", "material_lot"],
)
w.data_quality.create_monitor(monitor=Monitor(object_type="table", object_id=table.table_id, data_profiling_config=config))

알아 둘 점¶

  • inference·time series 프로파일은 처음 만들 때 최근 30일 데이터만 분석합니다. 그 뒤로는 새로 들어오는 데이터를 모두 처리합니다. 합성 데이터는 날짜가 지난 것이라, 시연 노트북이 시각을 최근 30일로 옮깁니다.
  • 갱신은 서버리스에서 돌고, 계정의 서버리스 활성화 여부와 관계없이 동작합니다. 테이블에 변경 데이터 피드(CDF) 를 켜 두면 새로 추가된 데이터만 처리해 비용이 줄어듭니다.
  • 예전 quality_monitors API는 지원 중단(deprecated)입니다. 새 코드는 w.data_quality를 씁니다.
  • 내부망에서 SDK를 올릴 수 없으면 화면(Catalog → 테이블 → Quality)에서 같은 설정으로 만듭니다.
  • Model Serving의 추론 테이블은 사설 엔드포인트로 보호된 스토리지에는 만들 수 없습니다. 내부망 구성에서는 오늘처럼 배치 예측 테이블을 감시 대상으로 삼습니다.
  • Korea Central 리전에서 Data quality monitoring을 지원합니다.
