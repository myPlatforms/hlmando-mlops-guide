2.1) (참고) 기존 보유 모델 등록¶

  • 데모 3분
  • 노트북 step2/2_1_register_existing_model
  • 참고

설비보전팀이 예전에 만든 모델 파일이 있다고 가정합니다. Databricks 밖에서 학습한 모델입니다. 이 모델을 Unity Catalog에 등록하면 새 모델과 같은 기준으로 비교하고 같은 방식으로 배포할 수 있습니다.

지금 모델이 어디 있나에 따라¶

경우 방법
① 파일만 있음 (pkl·joblib·ONNX·PyTorch .pth 등) Volume에 올림 → 불러오기 → mlflow.<flavor>.log_model 또는 pyfunc로 감싸 기록 → UC 등록 ← 이 데모. PyTorch 가중치(state_dict)는 아래 참고
② 다른 MLflow 서버·외부 환경 MLflow 모델 폴더를 옮겨 다시 기록하거나, 외부 환경에서 등록 대상을 Databricks UC로 바꿔 직접 등록
③ Databricks 구 Workspace Model Registry MlflowClient.copy_model_version() (MLflow 3.4.0 이상)
④ 학습 코드가 있음 코드를 옮겨 Databricks에서 다시 학습하는 것을 권장. 기존 모델은 기준선으로 등록해 비교

외부 학습 환경에서 Databricks로 바로 기록하는 방법은 세션 Q&A에 정리했습니다.

데모 순서¶

  1. Volume mlops_edu_dev.phm_shared.legacy_models의 README.json을 읽어 모델이 쓰는 컬럼과 라이브러리 버전을 확인합니다.
  2. joblib.load로 모델을 불러와 46~60일 구간에서 평가합니다. 원시 센서값 2개만 쓰는 모델이라 val_auc가 약 0.72로, Step 2 모델(약 0.94)보다 낮습니다.
  3. Step 2와 같은 래퍼(PHMFailureModel)로 감싸 기록하고 phm_legacy_model로 등록합니다. 별칭은 @baseline입니다.
  4. Experiments에서 legacy_baseline과 Step 2 실행 3개를 Compare 합니다.

꼭 챙길 것¶

  • UC 모델은 signature(입출력 스키마)가 필수입니다. 기존 모델에 없으면 등록할 때 만들어 넣습니다(infer_signature).
  • pickle은 여는 순간 그 안의 코드가 실행됩니다. 출처를 믿을 수 있는 파일만 엽니다.
  • 학습할 때 쓴 라이브러리 버전과 실행 환경 버전이 다르면 열리지 않을 수 있습니다. 버전을 기록해 두세요.
  • 사내 라이브러리가 필요하면 wheel을 Volume에 두고 extra_pip_requirements로 함께 기록합니다.
  • 내부망에서 Model Serving이 패키지를 못 받으면 두 가지로 대처합니다.
    • 워크스페이스 기본 패키지 저장소를 사내 미러로 설정합니다.
    • mlflow.models.utils.add_libraries_to_model()로 의존성을 wheel로 묶어 넣습니다.

PyTorch 가중치(.pth)와 설정(.yaml)으로 된 모델이라면¶

state_dict로 저장한 .pth에는 가중치만 들어 있습니다. 모델을 다시 만들려면 모델 클래스 정의 코드(nn.Module, .py)가 함께 있어야 합니다. 세 가지를 pyfunc 래퍼 하나로 묶어 기록합니다.

  • 가중치 .pth와 설정 .yaml: artifacts
  • 모델 정의 .py: code_paths
  • 전처리와 출력 형식: 래퍼 predict
import mlflow

class LegacyVisionModel(mlflow.pyfunc.PythonModel):
    def load_context(self, context):
        import torch, yaml
        from model_def import Net                       # your nn.Module definition
        cfg = yaml.safe_load(open(context.artifacts["config"]))
        self.model = Net(**cfg["model"])
        self.model.load_state_dict(torch.load(context.artifacts["weights"], map_location="cpu"))
        self.model.eval()

    def predict(self, context, model_input):
        ...                                             # decode image -> preprocess (from cfg) -> infer -> labels

info = mlflow.pyfunc.log_model(
    name="model",
    python_model=LegacyVisionModel(),
    artifacts={"weights": "/Volumes/<catalog>/<schema>/<volume>/model.pth",
               "config": "/Volumes/<catalog>/<schema>/<volume>/model.yaml"},
    code_paths=["/Volumes/<catalog>/<schema>/<volume>/model_def.py"],
    pip_requirements=["torch==<training version>", "torchvision==<training version>", "pyyaml"],
    signature=signature,                                # required for UC
    input_example=example,
)
mlflow.register_model(info.model_uri, "<catalog>.<schema>.<model name>")
순서 할 일
1 .pth·.yaml·모델 정의 .py·검증용 샘플(입력과 지금 운영 결과)을 Volume에 올립니다
2 학습 때와 같은 torch 버전 환경을 고릅니다(서버리스 Base environment ML 또는 pip 설치)
3 load_state_dict(strict=True)로 불러와 샘플 결과가 지금 운영 결과와 같은지 먼저 확인합니다
4 위 코드로 기록·등록하고 별칭 @baseline을 붙입니다
5 배포: 지금 컨테이너를 그대로 쓰려면 시작할 때 UC에서 @champion을 받아 MODEL_DIR에 둡니다(4장 엣지 앱과 같은 방식). 실시간 API가 필요하면 Model Serving(CPU·GPU)을 씁니다

미리 정리해 둘 것

모델 클래스 코드 위치 · yaml에 담긴 내용(구조 설정·클래스 이름·전처리 값) · 입력(이미지 크기·정규화)과 출력(분류·검출) · 학습 때 torch 버전 · 추론 하드웨어(GPU/CPU). Model Serving은 요청 한 건이 16 MB를 넘을 수 없으므로 이미지는 크기를 줄이거나 배치 추론을 씁니다.
