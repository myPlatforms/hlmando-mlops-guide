부록: 진행팀 운영표¶

고객 워크스페이스에는 엔드포인트·앱을 미리 만들어 둘 수 없으므로 당일 오프닝 중에 만듭니다. 엔드포인트는 8~16분(이 워크스페이스 사전 점검 실측), 앱은 약 5분 걸립니다.

당일 타임라인¶

시각 진행팀 화면 (뒤에서 실행) 참가자
전날까지 관리자 사전 설정 확인: 그룹 grp_mlops_edu(구성원·entitlement), 카탈로그 mlops_edu_dev 권한(그룹 ALL PRIVILEGES·진행팀 계정 MANAGE), 서버리스 컴퓨트·SQL 웨어하우스 Can use
08:40 로그인, mlops_edu_dev.phm_shared 데이터 확인(이미 생성됨. 없으면 00_setup/00_generate_data, 약 3분)
08:40 공용 모델 @champion 확인(드라이런 때 만들었으면 생략). 없으면 공용 모델 스키마(instructor)로 step1/1_data_and_features → step2/2_train_and_register Run all (약 6분)
08:50 00_setup/02_instructor_prep Run all: 참가자 권한, Serving 엔드포인트 생성 시작, 엣지 앱 배포. 마지막 셀 ready: READY 확인 오프닝 준비
09:15 엔드포인트 상태가 Updating이어도 진행 Step 0 시작
10:30 전 엔드포인트 Ready, 앱 Running 확인. 앱 URL을 채팅으로 공유 휴식 이후 Step 3
11:20 step5/5_1_data_quality_demo 실행 후 결과 시연 (첫 갱신은 몇 분 걸리므로 11:00쯤 미리 실행) Step 5
12:00 이후 00_setup/99_cleanup: 먼저 점검(dry run) → 엔드포인트·앱 삭제 각자 step0/0_setup_my_genie_code를 정리 = yes로 실행(선택)

막혔을 때¶

증상 대처
엔드포인트가 11:00까지 Ready가 안 됨 엔드포인트가 이미 있고 앱이 배포됐다면 클라우드 호출 사용을 끈 채 엣지 앱을 진행. 엔드포인트 생성 자체가 실패해 앱도 배포되지 않았다면 진행자 캡처로 대체
앱 배포 실패 (패키지 설치 등) 엣지 판정은 노트북으로 시연: 모델을 내려받아 로컬로 판정 (4.1)
참가자가 SQL 웨어하우스를 못 씀 Step 6 전에 참가자 그룹에 웨어하우스 Can use 부여
Genie Code 패널이 안 열림 관리자에게 Partner-powered AI features 확인. 그동안 노트북 실행 위주로 진행

비용과 정리¶

자원 남겨 두면
Serving 엔드포인트 (scale-to-zero) 호출이 없으면 거의 비용 없음. 호출되면 다시 켜짐
엣지 앱 실행 중이면 계속 과금 → 워크샵 직후 99_cleanup 또는 앱 화면에서 Stop
참가자 Job 스케줄이 없어 비용 없음
Data quality monitoring 프로파일 갱신할 때만 서버리스 비용
