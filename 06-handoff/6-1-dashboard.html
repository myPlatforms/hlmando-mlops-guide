6.1) ML Engineer 대시보드¶

기본 대시보드 정의(JSON)는 step6/phm_dashboard.py에 코드로 있습니다. 노트북이 내 스키마 이름을 넣어 대시보드를 만들고 게시합니다. 코드로 두면 Git으로 관리하고, 운영에서는 번들(resources의 dashboards)로 함께 배포할 수 있습니다.

1단계 - 대시보드 만들기¶

  1. step6/6_create_dashboard 노트북을 열고 내 스키마를 입력합니다. SQL 웨어하우스 ID는 비워 두면 서버리스 웨어하우스를 자동으로 고릅니다.
  2. Run all을 클릭합니다. 마지막 셀에 대시보드 열기 링크가 나옵니다.
  3. 링크로 대시보드를 열고 세 페이지를 넘겨 봅니다.
페이지 위젯 무엇을 보나
모델 성능 현재 champion 버전 · 최저 AUC · 검증 횟수, 구간별 AUC · 재현율 막대 신규 소재(LOT-N) 구간에서 성능이 떨어지고, 재학습한 버전이 회복하는지
검증 이력 승격/거부 원형, 검증 기록 표 파이프라인이 언제 왜 승격하거나 거부했는지 (Step 3 첫 실행 = 거부, Step 5 재학습 = 승격)
현장 경보 라인별 경보 수, 경보 vs 실제 결과, 설비별 최신 판정 설비보전팀에 보낼 점검 대상, 경보가 실제 고장과 맞았는지

다시 실행하면

같은 이름의 대시보드가 있으면 새로 만들지 않고 그 대시보드를 갱신합니다. 위젯을 화면에서 고쳤다면 다시 실행할 때 코드 내용으로 덮어쓰니 주의합니다.

2단계 - Genie Code로 위젯 추가하기¶

  1. 대시보드 오른쪽 위 Edit draft(초안 편집)를 클릭합니다.

  2. 오른쪽 위 Genie Code 아이콘으로 패널을 열고 아래처럼 요청합니다.

    Genie Code로 해 보기 · 위젯 추가

    '현장 경보' 페이지에 설비별 최근 24시간 고장 확률 추이를 선 그래프로 추가해줘. x축은 ts, y축은 fail_prob, 색은 machine_id로 하고 경보가 난 설비만 보여줘.

  3. 미리 보기를 확인하고 마음에 들면 Publish를 눌러 게시합니다.

운영에서 함께 보면 좋은 것 (시스템 테이블)

워크스페이스 관리자가 시스템 테이블 권한을 주면 같은 대시보드에 아래를 더할 수 있습니다. 오늘 참가자 권한으로는 보이지 않을 수 있어 넣지 않았습니다.

보고 싶은 것 시스템 테이블
학습 파이프라인 Job 성공률·소요 시간 system.lakeflow.job_run_timeline
엔드포인트 호출량·지연 system.serving 스키마의 서빙 사용량 테이블
워크샵·프로젝트별 비용 system.billing.usage (태그 project = mlops-workshop)
