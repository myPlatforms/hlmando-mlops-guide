6.2) 설비보전팀용 Genie Agent¶

기본 Genie Agent(구 Genie Space)는 데이터팀이 테이블·지시문·예시 쿼리를 정해 두면, 현업이 자연어로 묻는 채팅 공간입니다. 오늘은 ML팀이 설비보전팀을 위해 만듭니다.

1단계 - 만들기¶

  1. 왼쪽 사이드바 Genie Agents → 오른쪽 위 New를 클릭합니다.

  2. 데이터 원본으로 아래 4개를 고르고 Create를 클릭합니다.

    테이블 왜
    mlops_edu_dev.<내 스키마>.phm_predictions 설비별 고장 확률·경보
    mlops_edu_dev.<내 스키마>.model_monitoring 모델 성능 (구간별 AUC)
    mlops_edu_dev.phm_shared.equipment 설비·라인 정보
    mlops_edu_dev.phm_shared.maintenance_events 고장·예방정비 이력

  3. 만들면 Genie Code가 자동으로 열려 테이블 설명과 예시 쿼리를 제안합니다. 내용을 읽고 맞는 것만 받아들입니다.

2단계 - 지시문·질문 예 넣기¶

  1. Configure → Settings에서 제목을 VP1 설비 고장 위험 (<내 스키마>)로 바꾸고, Default warehouse에 서버리스 웨어하우스를 고릅니다.
  2. Common questions에 질문 예를 넣습니다. Instructions에 아래 지시문을 붙여넣습니다.
step6/genie_agent_instructions.md
# 설비보전팀용 Genie Agent — 지시문 (Instructions)

## 누가 쓰나
- HL만도 가상 공장 VP1의 설비보전팀. ML 용어를 모르는 현업 사용자다.
- 답은 한국어로, 짧게, 표로 정리한다. 숫자에는 단위와 기준 시각을 함께 쓴다.

## 용어
- `fail_prob`: 그 설비가 **24시간 안에 고장 날 확률**(0~1). 0.5는 "50%"라고 읽는다.
- `alert`: 점검 요청 **경보**. 모델 안에 저장된 경보 문턱값 이상이면 `true`.
- `fail_within_24h`: 실제로 24시간 안에 고장이 난 행(정답). 시뮬레이션 데이터라서 알 수 있다.
- `line_id`: 가공 라인(L1~L3). `machine_id`: 설비(M01~M24).
- `failure_mode`: BEARING = 베어링 마모, IMBALANCE = 불균형, OVERHEAT = 과열.
- `event_type`: FAILURE = 고장, PM = 예방정비.
- `material_lot` 'LOT-N': 61일째(2026-10-02)부터 투입된 신규 소재.

## 답하는 규칙
- "지금 위험한 설비"는 `phm_predictions`에서 설비마다 **가장 최근 `ts`** 의 `fail_prob`로 판단하고, 높은 순으로 보여 준다.
- 경보 수는 `alert = true`인 행 수가 아니라 **경보가 난 설비 수**로 답한다(같은 설비의 연속 경보는 1건).
- 모델 성능 질문은 `model_monitoring`의 구간별 `auc`·`recall_at_p50`으로 답하고, 0.8 미만이면 "ML팀 점검 필요"라고 덧붙인다.
- 고장 원인이나 정비 방법은 데이터에 없으므로 추측하지 말고 "설비보전 기준서 확인"이라고 답한다.

# 설비보전팀용 Genie Agent — 질문 예시와 벤치마크

## 시작 화면 질문 예시 (Sample questions)
1. 지금 고장 위험이 가장 높은 설비 5대는?
2. 라인별로 경보가 난 설비는 몇 대야?
3. 신규 소재(LOT-N) 투입 전후로 고장 유형이 어떻게 달라졌어?
4. 지금 쓰는 모델 버전과 최근 성능은?

## 벤치마크 (Benchmarks) — 질문과 정답 SQL
| 질문 | 정답 SQL (내 스키마로 바꿔 넣기) |
|---|---|
| 지금 고장 확률이 가장 높은 설비 3대 | `SELECT machine_id, line_id, round(fail_prob, 3) FROM mlops_edu_dev.<내 스키마>.phm_predictions QUALIFY row_number() OVER (PARTITION BY machine_id ORDER BY ts DESC) = 1 ORDER BY fail_prob DESC LIMIT 3` |
| 라인별 경보 난 설비 수 | `SELECT line_id, count(DISTINCT machine_id) FROM mlops_edu_dev.<내 스키마>.phm_predictions WHERE alert GROUP BY line_id ORDER BY line_id` |
| 1~60일 고장 유형별 건수 | `SELECT failure_mode, count(*) FROM mlops_edu_dev.phm_shared.maintenance_events WHERE event_type = 'FAILURE' GROUP BY failure_mode` |
| 61~90일 고장 유형별 건수 | `SELECT failure_mode, count(*) FROM mlops_edu_dev.phm_shared.maintenance_events_incoming WHERE event_type = 'FAILURE' GROUP BY failure_mode` |
| 구간별 champion AUC | `SELECT window, model_version, auc FROM mlops_edu_dev.<내 스키마>.model_monitoring ORDER BY window_start, model_version` |

3단계 - 물어보고 벤치마크로 확인하기¶

  1. 채팅에서 질문 예를 하나씩 물어봅니다. 답 아래 Show code로 Genie가 만든 SQL을 확인합니다.
  2. 벤치마크 질문과 정답 SQL을 등록하고 실행해, Genie의 답이 정답과 같은지 봅니다. 틀린 질문은 지시문이나 예시 SQL을 고쳐 다시 실행합니다.

관찰해 보세요

  • "라인별 경보 수"를 행 수가 아니라 설비 수로 답하나요? 지시문의 "답하는 규칙" 덕분입니다.
  • 정비 방법처럼 데이터에 없는 질문에는 지어내지 않고 "설비보전 기준서 확인"이라고 답하나요?

공유와 권한

  • Share에서 설비보전팀 그룹에 CAN RUN 권한을 줍니다.
  • 웨어하우스는 만든 사람의 자격 증명으로 실행되지만, 데이터는 질문한 사람의 Unity Catalog 권한으로 봅니다. 권한이 없는 테이블은 답에 나오지 않습니다.
  • Genie One과 Genie Agents는 사용자 사용량이 2027-01-31까지 무료입니다(서비스 주체 사용은 과금).

Step 6 완료

ML팀은 대시보드로 모델을 지켜보고, 설비보전팀은 Genie Agent로 결과를 묻습니다. 마무리로 이동합니다.
