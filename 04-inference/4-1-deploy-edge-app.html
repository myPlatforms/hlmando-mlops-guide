4.1) (참고) 엣지 앱 직접 배포하기¶

실습에서는 진행팀이 앱 하나를 배포해 두고 모두 같이 씁니다. 직접 배포해 보려면 아래 순서를 따르세요. 진행팀 준비 노트북 00_setup/02_instructor_prep의 3번과 같은 절차입니다.

앱 소스 (step4/edge_app/)¶

파일 내용
app.py Streamlit 화면: 모델 내려받기, 시뮬레이션, 상태 카드, 엣지·클라우드 판정 비교, 확률·센서 차트(Altair)
edge_sim.py 설비 센서 시뮬레이터 (데이터 생성기와 같은 규칙)
edge_features.py 엣지 피처 계산 (phm_features.py와 같은 정의, pandas). 판정은 마지막 1행, 차트는 전체 구간을 한 번에 계산
app.yaml 실행 명령(Databricks 색 테마 포함)과 환경 변수 (CATALOG, SERVING_ENDPOINT)
favicon.png 공식 사이트 파비콘을 앱 폴더에 포함한 파일(오프라인 사용)
requirements.txt mlflow-skinny[databricks], scikit-learn==1.6.1, pandas, numpy, streamlit>=1.50, databricks-sdk

배포 순서¶

  1. Compute → Apps → Create app → Custom을 고르고 이름을 입력합니다(예: vp1-edge-<이름>).
  2. App resources에 Serving 엔드포인트를 추가합니다. 리소스 키는 serving-endpoint, 권한은 Can query입니다.

  3. 앱이 만들어지면 Overview에서 앱의 서비스 주체 ID를 확인하고, 그 서비스 주체에 모델 읽기 권한을 줍니다. 아래 SQL은 카탈로그 소유자나 관리자가 실행합니다.

    GRANT USE CATALOG, USE SCHEMA, EXECUTE ON CATALOG mlops_edu_dev TO `<앱 서비스 주체 ID>`;

    실습에서는 참가자 모델을 모두 읽을 수 있도록 카탈로그 단위로 줬습니다. 운영에서는 앱(또는 엣지 배포 주체)이 쓸 모델에만 EXECUTE를 줍니다.

  4. Deploy를 누르고 소스 경로로 .../mlops_workshop/step4/edge_app을 지정합니다.

  5. 배포가 끝나면 앱 URL을 열어 4) 배포의 3단계를 진행합니다.

내부망에서 확인할 것¶

항목 내용
패키지 설치 앱은 시작할 때 requirements.txt를 설치합니다. 앱 기본 환경에는 streamlit·mlflow-skinny(구버전)는 있지만 scikit-learn이 없습니다. PyPI나 사내 미러에 닿지 않으면 wheel 파일을 앱 폴더에 함께 넣고 requirements.txt에서 파일 경로로 지정합니다
모델 파일 다운로드 앱이 UC 모델 파일을 받으려면 스토리지에 닿아야 합니다. 스토리지 방화벽을 쓰면 서버리스용 사설 엔드포인트(NCC) 구성이 필요합니다
DNS Private Link 환경에서는 *.databricksapps.com 조건부 DNS 포워딩이 필요합니다
대안 앱을 쓸 수 없으면 진행팀이 엣지 판정을 노트북으로 보여 줍니다(모델을 내려받아 로컬로 판정)
