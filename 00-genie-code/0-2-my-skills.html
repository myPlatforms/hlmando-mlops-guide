0.2) 내 스킬 설치¶

기본 스킬은 특정 작업에만 필요한 절차·예시를 묶은 폴더입니다. 인스트럭션은 모든 응답에 붙지만, 스킬은 요청 내용이 스킬 설명(description)과 맞을 때만 불러옵니다. 그래서 긴 절차를 넣어도 다른 작업에 방해가 되지 않습니다. 스킬은 Agent Skills 공개 형식을 따릅니다.

이 실습의 스킬 2종¶

1단계 - 설치 노트북 실행하기¶

  1. mlops_workshop/step0/0_setup_my_genie_code 노트북을 엽니다.
  2. 위젯 내 스키마에 영문 이름(예: juyeon)을 입력합니다.
  3. 서버리스에 연결하고 Run all을 클릭합니다. 내 스킬 2종과 0.3)의 내 인스트럭션이 한 번에 설치됩니다.

이미 내 인스트럭션이 있다면

노트북은 기존 파일을 지우지 않습니다. .bak으로 백업한 뒤, <!-- mlops-workshop:start -->와 end 표시 사이에 실습 구역만 넣습니다. 실습이 끝나면 위젯 정리를 yes로 바꿔 다시 실행하면 실습 구역과 스킬만 지워집니다.

2단계 - 확인하기¶

  1. Genie Code 패널 ⋮ → Customizations → Skills 탭을 엽니다. phm-mlflow-uc, phm-training-job이 User 스킬로 켜져(토글 On) 있는지 확인합니다.
  2. 새 채팅에서 @phm-training-job을 입력하면 스킬을 직접 지정할 수 있습니다. 지정하지 않아도 "학습 파이프라인 Job 구조를 알려줘" 같은 요청이면 Genie Code가 스킬을 골라 씁니다.

스킬을 고친 뒤에는 새 채팅

스킬 내용을 바꾸면 새 채팅을 열어야 반영됩니다. 그래도 옛 내용이 보이면 브라우저를 새로 고칩니다.

# PHM 모델 기록·등록 규칙 (실습)

## 실험 기록
- `mlflow.set_experiment(f"/Users/{ME}/phm_failure_{MY_SCHEMA}")`로 실험을 정한다.
- `mlflow.sklearn.autolog(log_models=False)`로 파라미터를 자동 기록하고, 모델은 아래 pyfunc로 직접 기록한다.
- 학습 데이터는 `mlflow.log_input(mlflow.data.load_delta(table_name=...), context="training")`으로 실행에 남긴다.
- 지표 이름은 고정한다: `val_auc`, `val_recall_at_p50`, `alert_threshold`.
  - `val_recall_at_p50`: 정밀도 0.5 이상(경보 2번 중 1번은 진짜)을 만족하는 문턱값에서의 재현율
  - `alert_threshold`: 그 문턱값. 모델 안에 함께 저장한다.

## 모델 형식
- `step2/phm_model.py`의 `PHMFailureModel(estimator, feature_columns, threshold)`로 감싼다. 출력은 `fail_prob`(float), `alert`(bool) 두 컬럼이다.
- `mlflow.pyfunc.log_model(name="model", python_model=..., code_paths=[<step2/phm_model.py 절대 경로>], signature=..., input_example=X.head(3))`
- signature는 `infer_signature(X.head(100), wrapper.predict(None, X.head(100)))`로 만든다. `product_code`·`is_5axis`는 int32다.

## Unity Catalog 등록·별칭
- 등록 이름: `mlops_edu_dev.<내 스키마>.phm_failure_model`. `mlflow.set_registry_uri("databricks-uc")`.
- 별칭 의미: `@champion` 운영 / `@challenger` 검증 대기 / `@previous` 직전 champion / `@baseline` 기존 모델(2.1).
- 노트북에서 `@champion`을 직접 옮기는 것은 Step 2 첫 등록뿐이다. 이후 승격은 학습 파이프라인 Job이 한다(`phm-training-job` 스킬).
- 버전 태그 `validation_status`(passed/failed)와 `validation_reason`은 파이프라인이 쓴다. 수동으로 바꾸지 않는다.

## 기존 모델 등록 (2.1)
- 파일(pkl·joblib)은 Volume에서 불러오되, **출처를 믿을 수 있는 파일만** 연다(pickle은 여는 순간 코드가 실행됨).
- 같은 래퍼로 감싸 signature를 붙이고 `mlops_edu_dev.<내 스키마>.phm_legacy_model`로 등록, 별칭 `@baseline`.
- 학습 때 라이브러리 버전을 `README.json` 또는 태그로 남긴다.

# PHM 학습 파이프라인 Job 규칙 (실습)

## 구조
- Job 이름: `phm_training_pipeline_<내 스키마>`. 태스크 4개를 순서대로 잇는다.

| 태스크 | 파일 | 하는 일 |
|---|---|---|
| `features` | `step3/task_features.py` | 피처 테이블 재생성 (`phm_features.py` 재사용) |
| `train` | `step3/task_train.py` | 학습 → 새 버전 등록 → `@challenger` |
| `validate` | `step3/task_validate.py` | 형식·최소 AUC·champion 대비 비교 → 버전 태그·`model_validation_log` 기록 |
| `promote` | `step3/task_promote.py` | 통과했을 때만 `@champion` 이동, 이전 버전은 `@previous` |

- 태스크 유형은 `spark_python_task`(Python 스크립트)다. 노트북 태스크로 바꾸지 않는다.
- 태스크 사이 상태는 UC 모델의 별칭·버전 태그로 넘긴다. 별도 파일·테이블에 상태를 저장하지 않는다.

## 파라미터
- Job 파라미터: `catalog`, `schema`, `valid_days`, `include_incoming`(true면 61~90일 데이터 포함, Step 5 재학습).
- 각 `.py`는 `pipeline_common.parse_args()`로 같은 인자(`--catalog --schema --lab_root --valid_days --include_incoming`)를 받는다. `lab_root`로 `step1`·`step2` 모듈을 불러온다.

## 컴퓨트
- 서버리스 환경 버전 5(`environment_version: "5"`)를 Job 환경으로 쓴다. 추가 의존성은 없다.
- 서버리스를 못 쓰면 실행 중인 DBR 17.3 LTS ML 클러스터(`existing_cluster_id`)를 쓴다.

## 결과 읽는 법
- 출력 줄은 `[features]` `[train]` `[validate]` `[promote]`로 시작한다.
- 같은 데이터로 다시 학습하면 `validate`가 `beats_champion=fail`로 막고 `promote`가 `not promoted`를 찍는다. **정상 동작**이다.
- `include_incoming=true`로 다시 돌리면 신규 소재 구간에서 champion보다 나아져 승격된다(예: v1 → v3).

## 운영 확장 (설명만)
- 같은 Job을 번들(`databricks.yml`, `resources/phm_training_pipeline.job.yml`)로 선언해 dev/staging/prod에 배포한다.
- 승인이 필요하면 `promote` 앞에 승인 단계를 둔다. 정기 재학습은 Job 스케줄, 데이터 도착 시 실행은 테이블 업데이트 트리거를 쓴다.

스킬을 잘 쓰는 법¶

  • 하나의 작업에 하나의 스킬. 범위가 좁을수록 Genie Code가 언제 쓸지 정확히 고릅니다.
  • 설명(description)에 실제로 쓰는 말을 넣습니다. "champion", "승격 안 됨"처럼 프롬프트에 쓸 단어를 넣으면 잘 불립니다.
  • 확인 값을 넣습니다. 행 수·AUC 같은 기대값을 적어 두면 Genie Code가 결과를 스스로 검증합니다.
  • Genie Code로 스킬 쓰기. "방금 한 기존 모델 등록 절차를 스킬로 정리해줘"처럼 초안을 맡기고 사람이 다듬습니다. 구축 기간에 ML팀이 반복하는 작업을 스킬로 남기면 팀의 운영 표준이 됩니다.
