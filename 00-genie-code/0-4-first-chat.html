0.4) 첫 대화: 공유 데이터 살펴보기¶

기본 노트북을 실행하기 전에 Genie Code와 함께 데이터를 먼저 둘러봅니다. Genie Code가 셀을 만들고 실행하는 에이전트 동작을 처음 보는 단계입니다.

1단계 - 빈 노트북 만들기¶

  1. Workspace → 내 mlops_workshop 폴더 → Create → Notebook을 클릭합니다. 이름은 0_genie_scratch로 합니다.
  2. 오른쪽 위 컴퓨트에서 Serverless를 고릅니다.
  3. 오른쪽 위 Genie Code 아이콘으로 패널을 엽니다.

2단계 - 데이터 둘러보기¶

  1. 아래 프롬프트를 보냅니다.

    프롬프트

    mlops_edu_dev.phm_shared의 테이블 목록과 각 테이블의 행 수를 표로 보여줘. 그리고 sensor_readings 컬럼의 뜻을 설명해줘.

  2. Genie Code가 계획을 먼저 말하고, 셀을 실행해도 되는지 묻습니다. 코드를 읽어 보고 Allow를 누릅니다.

  3. 결과를 소개의 표와 비교합니다. sensor_readings가 207,360행이면 맞습니다.

3단계 - 고장 이력 한 줄 요약¶

프롬프트

maintenance_events에서 고장(FAILURE)만 골라 고장 유형별 건수와 설비별 최다 고장 3대를 보여줘. 결과는 짧게 요약해줘.

고장은 80건(베어링 마모 41 · 불균형 20 · 과열 19)이면 맞습니다.

관찰해 보세요

  • Genie Code가 내 스키마가 아닌 phm_shared에 쓰려고 하지 않는지 확인합니다. AGENTS.md의 "읽기 전용" 규칙 덕분입니다.
  • 결과에 행 수·건수 같은 검증 값이 함께 나오나요? 내 인스트럭션의 "선호"가 적용된 것입니다.

4단계 - 오류 고치기 맛보기¶

  1. 새 셀에 일부러 틀린 코드를 넣고 실행합니다.

    spark.table("mlops_edu_dev.phm_shared.sensor_reading").groupBy("machine_id").count().display()

  2. TABLE_OR_VIEW_NOT_FOUND 오류 아래 Diagnose error를 누릅니다. Genie Code가 테이블 이름(sensor_readings)을 고친 코드를 제안합니다. Accept로 적용하고 다시 실행합니다.
